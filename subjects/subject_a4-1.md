### 4. 기능 요구 사항

다음 요구사항을 모두 만족해야 한다.

1. 데이터 준비 및 전처리
   - 최소 500개 이상의 문서가 포함된 텍스트 데이터셋을 사용한다.
   - 텍스트 정제(특수문자 제거, 소문자 변환 등)를 수행한다.
   - 토큰화를 구현한다. (한국어: 형태소 분석기 권장, 영어: NLTK 또는 공백 기반)
     - 한국어 형태소 분석기 설치가 어려운 환경의 경우, 공백 토큰화를 대안으로 사용하되 "성능이 왜 달라지는지"를 리포트에 분석한다.

   - 불용어 목록을 정의하고 제거한다.
   - 전처리 기준(특수문자 제거 범위, 불용어/동의어 처리 기준)을 학습자가 직접 설계하고 근거를 리포트에 서술한다.

2. TF-IDF 직접 구현
   - NumPy를 사용하여 TF-IDF 행렬을 계산하는 함수를 작성한다.
   - TF 계산: 문서 내 단어 빈도를 행렬로 표현한다.
   - IDF 계산: 전체 문서 대비 단어 출현 문서 수의 역수(로그 적용)를 계산한다.
   - 구현 결과를 Scikit-learn TfidfVectorizer와 비교하여 오차가 1e-6 이내인지 검증한다.
     - 검증 재현성 확보: sklearn의 sublinear_tf, smooth_idf, norm 등의 파라미터를 직접 구현체와 동일하게 설정하고, 어떤 설정으로 검증했는지 README에 명시한다.

3. 문서 검색 시스템
   - 쿼리를 TF-IDF 벡터로 변환한다.
   - 코사인 유사도를 NumPy 벡터 연산으로 직접 계산한다.
   - 유사도 상위 5개 문서를 반환한다. (점수, 문서 ID, 텍스트 스니펫 포함)

4. 문서 분류 실험
   - TF-IDF 벡터를 특성으로 사용하여 분류 모델을 학습한다.
   - 기본선: Logistic Regression 또는 Linear SVM 중 택1, Train/Test 8:2, random_state 고정
   - 정확도, F1-Score를 측정하고 혼동 행렬을 시각화한다.
   - 오분류된 문서 5개 이상의 원인을 분석한다. (BoW 한계와 연결하여 서술)

### 5. 보너스 과제

1.  다양한 TF 변형 구현
   - Raw Count, Log Normalization, Double Normalization 등 TF 계산 방식을 비교 구현한다.
   - 각 방식이 검색/분류 성능에 미치는 영향을 정량적으로 분석한다.

2. BM25 구현
   - BM25의 수식을 이해하고 NumPy로 직접 구현한다.
   - 동일한 쿼리에서 TF-IDF와 BM25 검색 결과를 비교 분석한다.

3. 역색인(Inverted Index) 구현
   - 단어 → 문서 ID 리스트 형태의 역색인 구조를 구현한다.
   - 역색인 기반 검색과 전체 스캔 검색의 시간 복잡도를 비교한다.

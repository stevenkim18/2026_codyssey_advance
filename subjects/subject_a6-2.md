분야: AI/SW 심화  
구분: 딥러닝  
학습시간: 80시간  
필수/선택: 필수

## 문제기술

### 기술적 설명

### 1. 미션 소개

실무에서 AI 모델링은 단순히 코드를 돌리는 것이 아니라, 성능 병목을 진단하고 개선하는 과정의 연속이다. 이 미션은 데이터 부족(Few-shot) 상황과 시계열 예측 문제를 해결하되, 체계적인 성능 진단(Diagnosis)과 오차 분석(Error Analysis)을 수행하는 데 중점을 둔다.

학습자는 Train/Validation/Test 셋의 성능 격차를 기반으로 모델의 상태(편향 vs 분산)를 진단해야 하며, 직접 학습 vs 사전학습 모델의 효용성을 실험을 통해 비교한다. 또한 딥러닝 모델이 단순 베이스라인보다 실제로 우수한지를 정량적으로 증명해야 한다. 이 과정은 향후 스마트팩토리, 핀테크 등 도메인 특화 프로젝트를 수행하기 위한 필수적인 기반이 된다.

본 미션은 이미지 전이학습(트랙 A)과 시계열 예측(트랙 B) 두 가지 트랙으로 구성된다.

두 트랙 모두 동일한 성능 개선 사이클을 따른다: (1) 베이스라인 설정 → (2) 딥러닝 모델 적용 → (3) 편향/분산 진단 및 오차 분석 → (4) 개선 적용 및 성과 정량화. 이 공통 프레임을 통해 학습자는 도메인이 달라도 적용 가능한 체계적 성능 개선 방법론을 구체화한다.

### 2. 최종 결과물

다음 내용이 모두 포함된 GitHub 레포지토리(Repository) URL을 제출한다.

1. 전이 학습(Transfer Learning) 및 시계열 예측(RNN) 모델 소스 코드
2. 성능 진단 리포트(Diagnosis Report) : 편향/분산 진단 및 해결 전략 기술 (Markdown)
3. 오차 분석표(Error Analysis Table) : 오분류된 데이터의 실패 원인 태깅 및 통계 (최소 30건 이상)
4. 베이스라인 비교 리포트 : 딥러닝 모델 vs 베이스라인 모델 성능 비교표
5. 실험 결과 시각화 (필수 4종) **:** Train/Val Loss 곡선, 예측 vs 실제 그래프, 베이스라인 비교 막대그래프, 오분류 이미지 갤러리
6. 누수 방지 근거 섹션: 시계열 분할/전처리 시 Data Leakage 방지 방법 기술 (Markdown)

### 3. 과제 목표

이 과제를 마친 후, 학습자는 아래를 스스로 설명할 수 있어야 한다.

- Train/Dev/Test 셋의 Loss 차이를 기반으로 높은 편향(Underfitting)과 높은 분산(Overfitting)을 진단할 수 있다.
- 전이 학습 시 데이터 크기에 따른 최적의 Fine-tuning 범위(Layer Freezing Strategy)를 결정할 수 있다.
- CNN(이미지)과 RNN(시계열) 모델의 구조적 차이와 적용 도메인을 구분할 수 있다.
- 오차 분석을 통해 모델이 실패하는 케이스의 패턴을 찾고 데이터 증강 전략을 수립할 수 있다.
- 딥러닝 모델과 베이스라인 모델의 성능 차이를 정량적으로 분석하고 해석할 수 있다.
- 시계열 데이터 처리 시 Data Leakage가 발생하는 구간을 식별하고, 이를 방지하는 전처리 원칙을 설명할 수 있다.

### 4. 기능 요구 사항

다음 요구사항을 모두 만족해야 한다.

1. Few-shot 전이 학습 및 오차 분석
   - 데이터가 적은(클래스당 50장 미만) 환경에서 CNN 기반 사전 학습 모델(ResNet, EfficientNet 등)을 활용해 전이 학습을 수행한다.
   - 분류기만 학습(Linear Probing) vs 전체 미세 조정(Fine-tuning)의 성능을 비교한다.
   - 학습 완료 후, 오분류된 이미지를 추출하여 실패 원인을 직접 확인하고 태깅하여 오차 분석표를 작성한다.
   - 추천 데이터셋 후보 (Few-shot 전이 학습용)

     | **데이터셋** | **출처** | **클래스 수** | **난이도** | **비고** |
     | --- | --- | --- | --- | --- |
     | Dogs vs Cats | Kaggle | 2 | 중 | 가장 접근성 높음 |
     | Food-101 (3~5개 클래스 선별) | Kaggle/TorchVision | 3~5 | 중~상 | 유사 클래스 변별력 학습 |
     | Oxford Flowers 102 (일부) | TorchVision | 5~10 | 상 | 미세 분류 도전 |
     | CIFAR-10 (일부 클래스) | TorchVision | 3~5 | 중 | 학습용 클래식 데이터 |

2. 시계열 예측 및 베이스라인 비교
   - yfinance 등을 통해 수집한 주가/경제 데이터를 LSTM/GRU(RNN 계열)로 예측한다.
   - 반드시 다음 베이스라인 모델 중 최소 2개를 구현하고 딥러닝 모델과 성능을 비교한다.

     | **베이스라인 모델** | **설명** | **수식/방법** |
     | --- | --- | --- |
     | Naive Forecast | 이전 시점 값을 그대로 예측 | ŷ(t) = y(t-1) |
     | 단순 이동평균 (SMA) | 최근 n일의 평균값 | ŷ(t) = (1/n)Σy(t-i) |
     | 지수 이동평균 (EMA) | 최근 값에 가중치 부여 | ŷ(t) = αy(t-1) + (1-α)ŷ(t-1) |
     | 선형 회귀 | 시간에 대한 선형 추세 | ŷ(t) = at + b |

   - 베이스라인과 딥러닝 모델의 성능을 MAE, RMSE, MAPE 지표로 비교하고, 딥러닝 모델이 베이스라인 대비 몇 % 우수한지 정량화한다.
   - 베이스라인 파라미터 가이드
     - SMA: 창(window) = 5, 10, 20일 중 선택하여 실험 (각각의 결과를 비교 권장)
     - EMA: α(alpha) = 0.1, 0.3, 0.5 중 선택 (값이 클수록 최근 값에 민감)
     - 선형 회귀: 입력 피쳐는 시간 인덱스 또는 지연값(lag feature) 기반으로 설정
     - 공정 비교 규칙: 모든 모델은 동일한 Test 구간에서 평가

   - 시계열 데이터 최소 기준
     - 1개 티커(종목), 최소 3년 일봉 데이터
     - Train/Validation/Test = 7/1/2 비율 (시간순 분할 필수)
     - 정규화는 반드시 Train 구간의 통계만으로 Fit (절대 Validation/Test 정보 사용 금지)

   - 대체 가능 시계열 데이터 옵션

     | **데이터** | **출처** | **특성** | **난이도** |
     | --- | --- | --- | --- |
     | 주가 데이터 (기본) | yfinance | 변동성 높음 | 중 |
     | 환율 데이터 | yfinance/FRED | 거시경제 변수 | 중 |
     | 전력 수요 데이터 | UCI/Kaggle | 계절성 두드러짐 | 중~상 |
     | 날씨 데이터 | Open-Meteo API | 다변량 시계열 | 중 |

     주의 : 금융 시계열에 Jittering/Time-warping 등 증강 기법을 적용하면 데이터 특성이 훼손될 수 있으므로, 시계열 증강은 적용 금지/주의 범주를 반드시 확인한다.

3. 편향/분산(Bias/Variance) 진단
   - 각 실험에서 Train Loss와 Validation Loss 곡선을 그린다.
   - 두 곡선의 격차(Gap)를 기반으로 현재 모델이 High Bias 상태인지 High Variance 상태인지 진단하고, 이에 따른 솔루션(예: 모델 복잡도 증가 vs 정규화)을 리포트에 명시한다.

     | 상태 | Train Loss | Val Loss | 해결책 |
     | --- | --- | --- | --- |
     | High Bias | 높음 | 높음 (비슷) | 모델 복잡도↑ |
     | High Variance | 낮음 | 높음 (큰 격차) | 정규화, 데이터↑ |

4. 데이터 누수(Data Leakage) 방지 체크포인트
   - 시계열 데이터 처리 시 다음 항목을 반드시 준수하고, 리포트에 근거를 기술한다.

   | No | 체크 항목 | 설명 |
   | --- | --- | --- |
   | 1 | 시간순 분할 | 반드시 시간 순서대로 Train → Validation → Test 분할 (shuffle 금지) |
   | 2 | 전처리 Fit 구간 제한 | Scaler.fit()은 Train 구간에만 적용, Validation/Test는 transform()만 사용 |
   | 3 | 윈도우 생성 규칙 | 입력 윈도우에 미래 시점 값이 포함되지 않도록 확인 (Look-ahead Bias 방지) |
   | 4 | 피쳐 생성 시점 | 지연값/이동평균 등 피쳐 생성은 분할 전에 수행하고, 문서에 근거 기술 |

5. 오차 분석 태그 체계 및 최소 기준
   - 오분류 이미지 태깅 시 다음 권장 카테고리를 참고하여 작성한다.

     | 태그 카테고리 | 예시 | 개선 방향 |
     | --- | --- | --- |
     | 데이터 품질 | 어두운 조명, 흐림, 해상도 부족 | 데이터 증강 |
     | 배경/잡음 | 복잡한 배경, 객체 가림 | 배경 제거/증강 |
     | 클래스 유사성 | 유사 품종, 형태적 유사성 | 특징 학습 강화 |
     | 라벨 오류 | 원본 데이터 라벨링 오류 의심 | 데이터 정제 |
     | 모델 한계 | 신뢰도는 높으나 잘못 예측, 변별력 부족 | 모델 구조 변경 |

### 5. 보너스 과제

1. Hyperparameter Tuning 전략
   - Grid Search 대신 Random Search 또는 Coarse-to-Fine 전략을 적용하여 최적의 하이퍼파라미터를 탐색한다.
   - 탐색 과정과 결과를 시각화하여 어떤 파라미터가 성능에 가장 큰 영향을 미쳤는지 분석한다.
   - 배움 포인트 : 효율적인 하이퍼파라미터 탐색 전략의 중요성을 체득한다.

2. Attention 메커니즘 적용
   - LSTM/GRU 모델에 Attention Layer를 추가하거나 Transformer 기반 모델을 적용해본다.
   - 배움 포인트 : 긴 시퀀스 데이터에서 중요 정보를 선별하는 Attention의 효과를 확인한다.

- 필수 시각화 그래프 가이드 :

  2. 예측 vs 실제 그래프 (시계열): X축 시간, Y축 값, 실제값(파란선) + 예측값(빨간선) 오버레이
  3. 베이스라인 비교 막대그래프: X축 모델명, Y축 MAE/RMSE, 모델별 성능 비교
  4. 오분류 이미지 갤러리: 태그별로 그룹화된 오분류 이미지 샘플

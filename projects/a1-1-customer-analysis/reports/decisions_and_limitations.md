# 의사결정 기록과 한계

분석 과정에서 내린 선택과 그 이유, 그리고 결과를 해석할 때 알아야 할 한계를 정리했습니다.

## 1. 데이터 선택과 준비

| 결정 | 선택 | 이유 | 영향 |
|---|---|---|---|
| 데이터셋 | H&M Personalized Fashion Recommendations (Kaggle 대회) | 실제 거래(고객, 날짜, 금액)와 상품 이미지, 상품명이 한 출처에 있음. 대안은 서로 다른 출처를 억지로 연결해야 함 | 원본이 약 4GB로 크고 대회 약관을 따라야 함 |
| 샘플링 | 고객 5,000명 무작위(`seed=42`) | 노트북에서 돌릴 수 있는 크기 | 거래가 없는 38명을 제외해 **고객 4,962명, 거래 113,723행, 상품 34,543개**(2018-09-20 ~ 2020-09-22) |
| 거래 필터링 | 이미지가 있는 상품으로 거래를 줄이지 않음 | 판매량 상위 3,000개 상품이 거래의 36.5%만 차지해서, 줄이면 고객 구매 이력의 절반 이상이 사라져 RFM이 왜곡됨 | 이미지 피처는 일부 거래에서만 실제 값을 가짐 |
| 금액 | `amount = price × 1000` | 원본 `price`는 정규화된 상대 금액(중앙값 약 0.025)이라 읽기 어려움 | 실제 통화 금액이 아님. 절대 매출이나 마진은 해석 불가 |

재현에 쓴 스크립트: `src/prepare_sample.py`, `src/download_images.py`, `src/build_image_array.py`. 실행 순서는 [README](../README.md)에 있습니다.

## 2. 이미지 확보 경위 (문제와 수정)

1. 판매량 상위 3,000개 상품의 이미지를 8개 병렬 요청으로 받았더니 **509장만 성공, 2,491건 실패**했습니다.
2. 처음에는 "이미지가 일부만 존재하는 것 같다"고 추정했습니다. **이 추정은 틀렸습니다.** Kaggle 전체 파일 목록(105,100개 이미지)을 받아 대조해 보니 샘플 상품의 99.8%에 이미지가 있었고, 실패한 2,491건 중 2,481건은 목록에 있는 파일이었습니다.
3. 실제 원인은 Kaggle API의 **요청 제한(HTTP 429)**이었고, 스크립트가 429와 404를 구분하지 않고 모두 "실패"로 기록한 것이 오해의 원인이었습니다.
4. 수정: 404와 429를 구분하고, 429가 오면 5, 10, 20, 40, 80초씩 늘려 가며 재시도하고, 워커를 2개로 낮추고, 목록에 있는 상품만 요청하도록 바꿨습니다.
5. 수정 후에도 속도가 느려 상위 1,000개 목표 중 **765장에서 중단**했습니다. 중단 시점까지 실패 35건이 쌓였는데, 스크립트를 도중에 끝내서 실패 사유 파일이 만들어지지 않아 원인은 확인하지 못했습니다 (429 재시도 소진으로 추정). 이미지 수는 765장으로 확정하고 분석했습니다.

결과적으로 이미지가 있는 거래는 18,952행(전체의 16.7%), 상품은 765개입니다.

## 3. 분석 방법의 선택

| 주제 | 선택 | 이유 |
|---|---|---|
| 결측치 대치 | 연령은 고객 단위 그룹 중앙값, 이미지 피처는 상품 단위 그룹 평균 (`unit_col`) | 거래 행 기준으로 평균을 내면 인기 상품이 평균을 좌우함 |
| 이미지 결측 처리 | `has_image` 플래그를 두고 이미지 분석은 해당 행으로 한정 | 83.3%가 대치값이라 그대로 믿으면 안 됨 |
| 이상치 처리 | 분포 분석은 클리핑, **RFM은 원본 금액** | 이상치는 입력 오류가 아니라 고가 상품의 정상 구매 |
| Frequency | 서로 다른 구매일 수 | 주문 번호가 없어서 행 수로 세면 장바구니 상품 수가 부풀려짐 |
| 점수 | 평균 순위 백분위를 5구간으로 올림 | 같은 값이 항상 같은 점수를 받도록 (`rank(method="first")`는 동점을 임의로 갈라 놓음) |
| Recency 기준일 | 마지막 거래일의 다음 날(2020-09-23) | 마지막 날 구매 고객의 Recency가 0이 되지 않게 |
| 월별 추이 | 첫 달(2018-09)과 마지막 달(2020-09) 제외 | 달의 일부만 포함돼 매출이 낮게 보임 |
| 색 | 범주는 막대 라벨로 구분하고 단일 파랑, 크기는 순차색, 상관은 발산색 | 6개 세그먼트를 색으로만 구분하면 색각 이상자가 구분하기 어려움 |

세그먼트 조건(VIP, Loyal 등)은 사람이 정한 규칙입니다. 기준을 바꾸면 세그먼트 크기가 달라집니다. 결과를 보고 기준을 조정하지 않았고, 처음 정한 규칙을 그대로 썼습니다.

## 4. 한계 (결과 해석 시 주의)

- **이미지 일반화**: 이미지 피처의 실제 값은 판매량 상위 765개 상품에만 있습니다. 이미지 관련 결과(밝기와 대비의 상관, 금액과의 관계)는 인기 상품에 대한 것이며 전체로 일반화할 수 없습니다.
- **피처 의미**: 흰 배경 위의 상품 사진이라 평균 밝기는 옷의 어두운 정도에 좌우됩니다. 밝기와 대비의 상관(약 -0.79)이 강해서 두 피처는 정보가 많이 겹칩니다.
- **관측 기간**: 약 2년입니다. Churned는 "관측 기간 안에서 오래 구매하지 않음"일 뿐 실제 이탈이 아닐 수 있습니다.
- **계절성**: 6월 매출 정점은 2개 연도만 본 결과라 계절성이라고 단정할 수 없습니다.
- **금액**: 정규화된 상대 값이라 마진, 쿠폰, 환불은 알 수 없습니다.
- **인과**: 상관과 세그먼트 비교는 연관을 보여 줄 뿐 원인을 증명하지 않습니다. 인사이트의 (검증) 항목에 추가로 필요한 데이터를 적었습니다.
- **쓰지 않은 컬럼**: `FN`, `Active`(절반 이상 결측), `sales_channel_id`(채널의 의미를 문서로 확인하지 못함)는 분석에 쓰지 않았습니다.

## 5. 확인하지 못한 것

- **대회 약관 원문**: 재배포와 공개 저장소 업로드 가능 여부를 확인하지 못했습니다. 안전하게 원본, 샘플, 이미지 배열을 저장소에서 제외했고(`.gitignore`), 이미지 article_id 목록(`data/processed/image_article_ids.csv`)만 남겼습니다. 제출 전에 약관을 직접 확인해야 합니다.
- **미션의 "공개 라이선스 우선" 권장**: H&M 데이터는 CC-BY나 MIT가 아니라 대회 약관을 따르므로 이 권장과 다릅니다.
- **이미지 재현성**: 요청 제한 때문에 다시 내려받으면 받아지는 이미지 수가 달라질 수 있고, 그러면 이미지 관련 수치도 달라집니다.

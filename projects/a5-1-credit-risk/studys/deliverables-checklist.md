# 신용 위험 예측 과제: 평가 결과물 정리

이 과제에서 평가자에게 보여줘야 할 결과물은 크게 **데이터, 예측 모델, 성능 비교, 시각화, 프로젝트 문서**입니다. 아래 순서대로 보여주면 과제의 흐름도 자연스럽게 전달할 수 있습니다.

---

## 1. 가상 고객 데이터

과제에서 제공한 생성 코드를 실행해 고객 데이터 **10,000건**을 만들어야 합니다.

| 보여줄 항목 | 프로젝트 결과 |
|---|---|
| 데이터 파일 | `data/finance_data.csv` |
| 고객 수 | 10,000명 |
| 입력 변수 | 나이, 연 소득, 소비 점수, 부채 비율, 카드 수, 최근 6개월 연체 횟수 |
| 예측할 정답 | 신용 점수 `credit_score`, 연체 여부 `is_overdue` |
| 연체 고객 비율 | 12.01% |

**설명 포인트**

> 제공된 코드로 데이터를 생성했고, 회귀와 분류에 사용할 정답이 하나의 데이터셋에 함께 들어 있습니다. 연체 고객이 약 12%라서 데이터 불균형이 있습니다.

CSV 파일은 Git에 올라가지 않으므로 평가자가 처음 실행할 때 생성해야 합니다. 다음 명령은 저장소 루트에서 실행합니다.

```bash
cd projects/a5-1-credit-risk
uv run python -m src.data_gen
```

관련 파일: [데이터 생성 코드](../src/data_gen.py)

## 2. 규칙 기반 모델과 머신러닝 모델의 성능 비교표

사람이 직접 만든 규칙과 머신러닝 모델이 같은 테스트 데이터에서 어떤 성능을 보였는지 보여줘야 합니다.

| 모델 | 정확도 | 정밀도 | 재현율 | F1 | AUC |
|---|---:|---:|---:|---:|---:|
| 규칙 기반 모델 | 0.850 | 0.426 | 0.717 | 0.534 | 0.878 |
| 로지스틱 회귀 | 0.878 | 0.496 | 0.879 | 0.635 | 0.950 |
| 랜덤 포레스트, 튜닝 | 0.897 | 0.551 | 0.771 | 0.642 | 0.942 |

**설명 포인트**

> 규칙 기반 모델은 사람이 만든 다섯 개 규칙 중 두 개 이상에 해당하면 연체 위험으로 판단합니다. 머신러닝 모델은 같은 테스트 데이터에서 규칙 기반 모델보다 높은 F1과 AUC를 보였습니다.

규칙 기반 모델의 AUC는 확률 대신 **발동한 규칙의 개수**를 위험 점수로 사용해 계산했습니다.

실행 명령:

```bash
uv run python -m src.baseline
uv run python -m src.classification
```

결과표는 [프로젝트 README](../README.md)에도 정리되어 있습니다.

## 3. 신용 점수 예측 결과 — 회귀

고객 정보를 입력해 **0~1000점의 신용 점수**를 예측하는 결과를 보여줍니다.

필수 모델은 **Ridge와 Lasso**입니다.

### 성능 비교표

| 모델 | RMSE | MAE | R² |
|---|---:|---:|---:|
| Ridge | 30.134 | 23.933 | 0.861 |
| Lasso | 30.131 | 23.928 | 0.861 |

**설명 포인트**

> 두 모델 모두 신용 점수를 평균적으로 약 24점 차이로 예측했습니다. RMSE는 큰 오차에 더 민감한 지표이고, R²는 평균만 예측하는 기준보다 얼마나 나아졌는지 보여줍니다.

### 함께 보여줄 그래프

1. [Alpha별 계수 변화 그래프](../outputs/regression_coef_path.png)  
   규제 강도인 Alpha를 바꿨을 때 Ridge와 Lasso의 계수가 어떻게 달라지는지 보여줍니다.
2. [예측 점수와 실제 점수 비교 그래프](../outputs/regression_pred_vs_actual.png)  
   예측 점수가 실제 점수와 얼마나 가까운지 보여줍니다.

**규제 그래프 설명 포인트**

> Alpha가 커질수록 규제가 강해집니다. Lasso는 일부 계수를 0으로 만들 수 있으며, 이 실험에서 규제를 너무 강하게 적용했을 때는 필요한 정보까지 제거돼 성능이 떨어졌습니다.

실행 명령:

```bash
uv run python -m src.regression
```

## 4. 연체 위험 예측 결과 — 분류

고객 정보를 입력해 **연체 위험 점수**를 예측하고, 기준에 따라 연체 위험과 정상으로 분류한 결과를 보여줍니다.

### ① Confusion Matrix

[혼동 행렬 그래프](../outputs/classification_confusion_matrix.png)

다음 네 가지 결과가 얼마나 발생했는지 보여주는 표입니다.

| | 실제 연체 | 실제 정상 |
|---|---|---|
| 연체 위험이라고 예측 | 연체 고객을 올바르게 찾아냄 | 정상 고객을 위험하다고 잘못 판단 |
| 정상이라고 예측 | 연체 고객을 놓침 | 정상 고객을 올바르게 판단 |

**설명 포인트**

> 모델이 연체 고객을 얼마나 찾아냈는지뿐 아니라, 정상 고객을 얼마나 잘못 분류했는지도 확인할 수 있습니다.

### ② ROC 곡선과 AUC

[ROC 곡선 그래프](../outputs/classification_roc_curve.png)

임계값을 바꾸면서 모델이 연체 고객과 정상 고객을 얼마나 잘 구분하는지 보여줍니다. 그래프 범례에 AUC 값이 표시되어 있습니다.

**설명 포인트**

> AUC가 1에 가까울수록 두 집단의 위험 순위를 잘 구분합니다. 로지스틱 회귀의 AUC는 0.950, 튜닝한 랜덤 포레스트는 0.942였습니다.

실행 명령:

```bash
uv run python -m src.classification
```

## 5. 데이터 불균형 처리 비교 결과

연체 고객이 전체의 약 12%로 적기 때문에, 불균형을 처리한 모델과 처리하지 않은 모델을 비교해 보여줍니다.

| 로지스틱 회귀 | 정밀도 | 재현율 | F1 |
|---|---:|---:|---:|
| 처리 없음 | 0.710 | 0.571 | 0.633 |
| 클래스 가중치 적용 | 0.496 | 0.879 | 0.635 |
| SMOTE 적용 | 0.514 | 0.867 | 0.645 |

**설명 포인트**

> 클래스 가중치와 SMOTE를 적용하자 연체 고객을 더 많이 찾아냈습니다. 대신 정상 고객을 위험 고객으로 잘못 판단하는 경우도 늘어 정밀도는 낮아졌습니다.

특히 다음 두 가지를 설명할 수 있으면 좋습니다.

- **클래스 가중치**: 소수인 연체 고객을 틀렸을 때 학습 과정에서 더 큰 벌점을 줍니다.
- **SMOTE**: 기존 연체 고객을 참고해 학습용 가상 샘플을 만듭니다. 테스트 데이터에는 적용하지 않습니다.

## 6. 랜덤 포레스트 튜닝 결과

앙상블 모델로 **랜덤 포레스트**를 사용했고, `GridSearchCV`로 설정을 비교했습니다.

| 탐색 항목 | 후보 |
|---|---|
| 트리 개수 | 100, 200, 300 |
| 최대 깊이 | 4, 6, 8, 12, 제한 없음 |
| 잎 노드의 최소 샘플 수 | 1, 5, 10, 20 |
| 총 조합 | **60개** |
| 평가 방법 | **5겹 교차 검증**, F1 기준 |
| 선택된 설정 | 트리 300개, 최대 깊이 12, 최소 샘플 수 1 |

**설명 포인트**

> 랜덤 포레스트 설정 60개를 학습 데이터에서 5겹 교차 검증으로 비교했습니다. 다만 튜닝한 모델이 테스트 데이터에서 기본 모델보다 항상 더 좋은 것은 아니었습니다.

## 7. 전처리와 데이터 누수 방지 구조

이 부분은 그래프보다 **코드와 흐름을 설명**하면 됩니다.

```text
데이터 10,000건
       ↓
학습 8,000건 / 테스트 2,000건 분할
       ↓
학습 데이터로만 전처리 기준 계산
       ↓
모델 학습
       ↓
테스트 데이터로 성능 확인
```

| 항목 | 구현 내용 |
|---|---|
| 데이터 분할 | 8:2, 연체 여부 기준 층화 분할 |
| 재현성 | `random_state=42` |
| 수치형 변수 | 결측값 대치 후 표준화 |
| 범주형 변수 | 연령대로 변환 후 원-핫 인코딩 |
| 전처리 구조 | `Pipeline`, `ColumnTransformer` |
| 누수 방지 | 전처리와 SMOTE를 학습 데이터에서만 적용 |

**설명 포인트**

> 테스트 데이터의 정보를 미리 사용하지 않도록 먼저 데이터를 나눴습니다. 평균과 표준편차 같은 전처리 기준은 학습 데이터에서만 계산했습니다.

관련 파일: [전처리 코드](../src/preprocess.py)

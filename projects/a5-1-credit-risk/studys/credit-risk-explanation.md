# 신용 위험 예측 과제: 선수 개념부터 발표까지

이 문서는 다른 사람에게 과제를 설명할 때 **어떤 문제를 풀려고 했는가 → 무엇을 알아야 하는가 → 어떻게 만들었는가 → 결과가 어땠는가** 순서로 이야기할 수 있도록 정리한 자료입니다.

각 단계에 직접 말할 수 있는 설명도 함께 담았습니다.

---

# 1단계. 먼저, 이 과제가 해결하려는 문제

## 이렇게 시작해 보세요

> 은행이 대출 신청을 받았을 때, 고객이 나중에 연체할 가능성이 있는지 판단해야 합니다.
>
> 이 과제에서는 가상의 고객 데이터를 이용해 신용 점수와 연체 위험을 예측하는 모델을 만들었습니다.
>
> 그리고 사람이 직접 만든 판단 규칙과 머신러닝 모델 중 어느 쪽이 더 좋은 결과를 내는지 비교했습니다.

여기서 핵심 질문은 두 가지입니다.

1. 이 고객의 **신용 점수는 몇 점일까?**
2. 이 고객은 **연체할 위험이 얼마나 될까?**

예를 들어 고객에 대한 정보가 다음과 같다고 해볼게요.

```text
나이: 35세
연 소득: 4,000만 원
부채 비율: 0.6
최근 6개월 연체: 1회
```

이 정보를 보고 모델이 다음처럼 답하는 것입니다.

```text
예상 신용 점수: 420점
예상 연체 위험 점수: 0.65
```

이 두 질문을 이해하려면 먼저 **데이터와 머신러닝의 기본 개념**을 알아야 합니다.

---

# 2단계. 선수 개념: 데이터, 특성, 정답

머신러닝은 기본적으로 **과거 사례를 보고 패턴을 찾는 방법**입니다.

이 과제의 데이터는 고객별 정보가 한 줄씩 들어 있는 표라고 생각하면 됩니다.

| 고객 | 나이 | 연 소득 | 부채 비율 | 연체 횟수 | 신용 점수 | 연체 여부 |
|---|---:|---:|---:|---:|---:|---|
| A | 35세 | 4,000만 원 | 0.6 | 1회 | 420점 | 연체 |
| B | 42세 | 6,000만 원 | 0.2 | 0회 | 510점 | 정상 |

이 표에서 용어가 세 가지 나옵니다.

## ① 샘플: 한 명의 고객

표의 한 줄이 하나의 **샘플**입니다.

이 프로젝트는 가상의 고객 **10,000명**, 즉 10,000개의 샘플을 사용합니다.

## ② 특성: 예측할 때 참고하는 정보

나이, 연 소득, 부채 비율, 연체 횟수처럼 모델이 예측할 때 참고하는 정보를 **특성(Feature)** 또는 **입력 변수**라고 합니다.

이 프로젝트의 입력 변수는 총 6개입니다.

```text
나이
연 소득
소비 점수
부채 비율
신용카드 수
최근 6개월 연체 횟수
```

## ③ 타깃: 모델이 맞혀야 하는 정답

모델이 예측해야 하는 값을 **타깃(Target)**이라고 합니다.

이 과제에는 정답이 두 개 있습니다.

```text
타깃 1: 신용 점수
타깃 2: 연체 여부
```

## 설명할 때는 이렇게

> 고객 한 명을 하나의 샘플로 보고, 소득이나 부채 비율처럼 예측에 참고하는 정보를 특성이라고 합니다. 그리고 모델이 맞혀야 하는 신용 점수와 연체 여부를 타깃이라고 합니다.

# 3단계. 선수 개념: 지도학습과 머신러닝

## 지도학습이란?

시험공부에 비유해 보겠습니다.

문제와 정답이 함께 있는 문제집을 보고 공부하면, 나중에는 비슷한 새 문제도 풀 수 있습니다.

머신러닝도 비슷합니다.

```text
고객 정보 + 실제 신용 점수
          ↓
       모델이 학습
          ↓
새 고객 정보 → 신용 점수 예측
```

입력 정보와 정답을 함께 보여주며 학습시키는 방식을 **지도학습**이라고 합니다.

이 프로젝트에서는 다음 두 가지를 학습합니다.

```text
고객 정보 + 실제 신용 점수 → 신용 점수 예측 모델
고객 정보 + 실제 연체 여부 → 연체 위험 예측 모델
```

## 사람이 규칙을 만드는 방식과의 차이

사람이 직접 규칙을 만들 수도 있습니다.

```text
연체 횟수가 2회 이상이면 위험
부채 비율이 0.8보다 크면 위험
```

이 방식에서는 **사람이 기준을 직접 정합니다.**

반면 머신러닝에서는 많은 고객의 정보와 정답을 보여주고, **어떤 정보가 정답과 관련 있는지 모델이 학습**합니다.

## 설명할 때는 이렇게

> 이 과제는 정답이 있는 데이터를 이용하는 지도학습입니다. 사람이 연체 기준을 직접 정한 규칙 기반 모델을 만들고, 데이터에서 패턴을 학습한 머신러닝 모델과 비교했습니다.

---

# 4단계. 선수 개념: 회귀와 분류

같은 머신러닝이라도 **무엇을 예측하느냐**에 따라 문제의 종류가 달라집니다.

## ① 회귀: 숫자를 예측

회귀는 연속적인 숫자를 예측하는 문제입니다.

```text
고객 정보 → 신용 점수 420점
```

다른 예로는 집값, 기온, 매출액 예측이 있습니다.

이 프로젝트에서는 **신용 점수 예측**이 회귀입니다.

## ② 분류: 종류를 예측

분류는 어떤 대상을 정해진 범주 중 하나로 나누는 문제입니다.

```text
고객 정보 → 연체 위험 / 정상
```

다른 예로는 스팸 메일 판별, 불량품 판별이 있습니다.

이 프로젝트에서는 **연체 여부 예측**이 분류입니다.

## 연체 확률과 분류의 관계

분류 모델은 먼저 보통 0에서 1 사이의 위험 점수를 출력합니다.

```text
고객 A: 0.8
고객 B: 0.3
```

그리고 기준을 정해 범주를 나눕니다. 기준이 0.5라면:

```text
0.5 이상 → 연체 위험
0.5 미만 → 정상
```

이 기준을 **임계값(Threshold)**이라고 합니다.

0.5는 모델 비교를 위해 정한 기준이며, 실제 대출 심사에서 반드시 0.5를 사용해야 한다는 뜻은 아닙니다.

또한 모델이 출력한 0.8이 실제 연체 확률 80%와 정확히 일치하는지는 별도의 **확률 보정** 확인이 필요합니다.

## 설명할 때는 이렇게

> 신용 점수처럼 숫자를 예측하는 문제는 회귀이고, 연체와 정상처럼 종류를 나누는 문제는 분류입니다. 이 과제에서는 같은 고객 데이터로 두 문제를 모두 다뤘습니다.

# 5단계. 이제 이 과제의 데이터 설명하기

기본 개념을 설명했다면 실제 데이터로 넘어갑니다.

## 이렇게 설명해 보세요

> 실제 고객 데이터를 사용한 것은 아니고, 과제에서 제공한 코드로 가상의 고객 10,000명을 만들었습니다.
>
> 각 고객에게 나이, 소득, 부채 비율 등의 정보를 부여하고, 이를 바탕으로 신용 점수와 연체 여부를 생성했습니다.

## 신용 점수는 어떻게 만들었나?

신용 점수는 대략 다음 방식으로 만들어졌습니다.

```text
기본 점수
+ 소득이 높을수록 점수 증가
- 연체 횟수가 많을수록 점수 감소
- 부채 비율이 높을수록 점수 감소
+ 무작위 잡음
```

여기서 **잡음(Noise)**은 예측하기 어려운 무작위 변동입니다.

예를 들어 두 고객의 소득과 연체 횟수가 같더라도 점수가 완전히 같지는 않도록 작은 차이를 주는 것입니다.

## 연체 여부는 어떻게 만들었나?

먼저 신용 점수가 낮은 고객을 찾은 다음, 그중 일부를 연체 고객으로 정했습니다.

생성 결과:

```text
전체 고객: 10,000명
연체 고객: 1,201명
정상 고객: 8,799명
```

즉, 연체 고객이 전체의 약 **12%**입니다.

이 생성 방식을 알아야 나중에 “왜 모델이 이런 성능을 냈는지” 설명할 수 있습니다.

## 꼭 덧붙일 한계

> 실제 은행 기록이 아니라 수식으로 생성한 가상 데이터이기 때문에, 이 결과를 실제 대출 심사의 성능으로 일반화할 수는 없습니다.

# 6단계. 선수 개념: 학습과 시험은 왜 나눌까?

머신러닝 모델의 실력을 알려면 **공부할 때 본 문제와 시험 문제를 분리**해야 합니다.

시험 문제를 미리 외웠다면 높은 점수를 받아도 새로운 문제를 잘 풀 수 있는지는 알 수 없습니다.

머신러닝도 같습니다.

```text
전체 데이터 10,000명
          │
          ├─ 학습 데이터 8,000명
          │     모델을 학습하고 설정을 고르는 데 사용
          │
          └─ 테스트 데이터 2,000명
                학습에 사용하지 않은 데이터로 성능 확인
```

이 프로젝트는 **8:2 비율**로 분할했습니다.

또한 연체 고객이 약 12%이므로, 학습 데이터와 테스트 데이터에도 연체 고객이 비슷한 비율로 들어가도록 했습니다. 이를 **층화 분할**이라고 합니다.

## 설명할 때는 이렇게

> 모델이 학습한 데이터를 그대로 평가하면 실력이 부풀려질 수 있습니다. 그래서 고객 10,000명을 학습용 8,000명과 테스트용 2,000명으로 나눴습니다.

---

# 7단계. 선수 개념: 전처리는 왜 필요할까?

데이터를 모델에 바로 넣기 전에 형태를 정리하는 작업을 **전처리**라고 합니다.

요리하기 전에 재료를 씻고 손질하는 과정과 비슷합니다.

## ① 결측값 처리

어떤 고객의 소득이 비어 있다면, 모델이 처리할 수 있도록 적절한 값으로 채웁니다.

이 프로젝트에서는 숫자 데이터가 비어 있으면 학습 데이터의 **중앙값**으로 채우도록 만들었습니다.

다만 이번에 생성한 원본 데이터에는 결측값이 없기 때문에, 실제로 채워진 값은 없습니다.

## ② 스케일링

변수마다 숫자의 크기가 다릅니다.

```text
연 소득: 4,000
부채 비율: 0.6
연체 횟수: 1
```

이런 숫자를 그대로 쓰면 일부 모델에서 변수의 크기 차이가 학습이나 규제에 영향을 줄 수 있습니다.

그래서 각 변수의 크기를 비교하기 좋게 맞춥니다. 이 프로젝트에서는 **표준화**를 사용했습니다.

## ③ 범주형 데이터 변환

나이를 20대, 30대 같은 연령대로 바꾸고, 이를 모델이 다루기 쉬운 숫자 열로 변환했습니다.

```text
30대 → 20대 여부: 0 / 30대 여부: 1 / 40대 여부: 0
```

이 방법을 **원-핫 인코딩**이라고 합니다.

## ④ Pipeline

이러한 과정을 모델과 하나로 묶었습니다.

```text
고객 데이터
   ↓
결측값 처리
   ↓
스케일링 또는 인코딩
   ↓
모델 예측
```

이렇게 작업 순서를 하나로 묶은 것을 **Pipeline**이라고 합니다.

## 설명할 때는 이렇게

> 데이터를 모델에 넣기 전에 결측값 처리, 스케일링, 범주형 변수 인코딩을 했습니다. 이 과정을 모델과 파이프라인으로 묶어 학습과 예측 시 같은 방식으로 처리하도록 했습니다.

# 8단계. 선수 개념: 데이터 누수란?

앞에서 학습과 시험 데이터를 나눈 이유를 설명했죠. 여기서 한 단계 더 나아가면 **데이터 누수**를 이해할 수 있습니다.

데이터 누수는 **모델이 실제 예측 시점에 알아서는 안 되는 정보를 학습이나 평가 과정에서 미리 이용하는 것**입니다.

## 예시 1: 테스트 데이터를 보고 평균을 구한 경우

스케일링을 할 때 전체 고객 10,000명의 평균을 먼저 구하면, 테스트 고객의 정보도 계산에 들어갑니다.

```text
잘못된 순서

전체 데이터로 평균 계산
          ↓
학습 / 테스트 분리
```

시험 문제의 정보를 미리 본 것과 비슷합니다.

올바른 순서는 다음과 같습니다.

```text
학습 / 테스트 분리
          ↓
학습 데이터로만 평균 계산
          ↓
그 평균을 학습과 테스트 데이터에 동일하게 적용
```

## 예시 2: 정답을 만드는 데 사용된 정보

이 데이터에서는 신용 점수를 바탕으로 연체 여부를 만들었습니다.

따라서 연체를 예측할 때 신용 점수를 입력하면 모델이 정답에 매우 가까운 정보를 받게 됩니다.

실제로 프로젝트에서 실험했을 때:

```text
신용 점수 없이 연체 예측: AUC 0.940
신용 점수를 넣어 연체 예측: AUC 0.984
```

다만 **신용 점수를 사용하는 것이 모든 상황에서 무조건 누수는 아닙니다.** 실제 예측 시점에 합법적이고 적절하게 사용할 수 있는 정보인지가 중요합니다.

이 과제에서는 신용 점수가 연체 정답을 만드는 데 직접 사용되었으므로, 이를 입력하면 원래 비교하려던 문제보다 유리해진다고 설명하는 것이 정확합니다.

## 설명할 때는 이렇게

> 데이터 누수를 방지하기 위해 데이터를 먼저 분할하고, 전처리는 학습 데이터로만 기준을 계산했습니다. 또한 연체 여부를 만드는 데 사용된 신용 점수를 연체 예측 입력에 넣으면 성능이 크게 높아질 수 있다는 점도 별도로 확인했습니다.

---

# 9단계. 규칙 기반 모델부터 설명하기

이제 실제 모델링 내용을 설명할 준비가 됐습니다.

먼저 **비교 기준**, 즉 베이스라인을 설명합니다.

## 베이스라인이란?

새로운 모델이 잘하는지 알려면 비교할 기준이 필요합니다.

예를 들어 학생의 성적이 80점이라도 시험 평균이 95점이면 높은 점수라고 보기 어렵습니다.

머신러닝에서도 마찬가지로, “복잡한 모델을 쓰기 전에 간단한 방법으로는 얼마나 맞힐 수 있는가?”를 먼저 확인합니다.

그 기준을 **베이스라인(Baseline)**이라고 합니다.

## 이 프로젝트의 베이스라인

사람이 다섯 가지 규칙을 직접 만들었습니다.

예를 들면:

```text
규칙 1. 최근 6개월 연체가 2회 이상인가?
규칙 2. 부채 비율이 0.8보다 큰가?
규칙 3. 연 소득이 3,000만 원보다 낮은가?
...
```

그리고 다음과 같이 판단합니다.

```text
5개 규칙 중 2개 이상 해당 → 연체 위험
그 외 → 정상
```

두 개라는 기준은 학습 데이터에서 F1 점수를 비교해 정했습니다.

## 설명할 때는 이렇게

> 먼저 사람이 직접 만든 다섯 개의 규칙을 비교 기준으로 사용했습니다. 규칙 두 개 이상에 해당하면 연체 위험으로 판단하도록 하고, 이후 머신러닝 모델과 같은 테스트 데이터에서 성능을 비교했습니다.

# 10단계. 선수 개념: 분류 모델의 성적표 읽기

모델을 만들었으면 잘 맞혔는지 확인해야 합니다.

여기서는 **연체 고객을 찾아내는 상황**으로 생각하면 쉽습니다.

## 먼저, 네 가지 결과

| | 실제 연체 고객 | 실제 정상 고객 |
|---|---|---|
| **연체 위험이라고 예측** | 맞게 찾아냄 | 정상 고객을 위험하다고 잘못 판단 |
| **정상이라고 예측** | 연체 고객을 놓침 | 맞게 정상이라고 판단 |

이 표를 **혼동 행렬(Confusion Matrix)**이라고 합니다.

이제 이 표를 바탕으로 여러 지표를 계산합니다.

## ① 정확도 Accuracy

> 전체 고객 중 몇 명을 맞혔는가?

```text
정확도 = 맞게 예측한 고객 수 / 전체 고객 수
```

그런데 이 과제는 연체 고객이 12%밖에 없습니다.

만약 모델이 모든 고객에게 무조건 “정상”이라고 한다면?

```text
정확도: 약 88%
연체 고객을 찾아낸 수: 0명
```

정확도는 높아 보이지만, 연체 고객을 찾는 목적은 달성하지 못합니다.

## ② 재현율 Recall

> 실제 연체 고객 중 몇 명을 찾아냈는가?

```text
실제 연체 고객 100명
그중 80명을 위험 고객으로 찾음

→ 재현율 80%
```

재현율이 높으면 **연체 고객을 덜 놓칩니다.**

## ③ 정밀도 Precision

> 위험하다고 예측한 고객 중 실제 연체 고객은 몇 명인가?

```text
위험하다고 예측한 고객 100명
그중 실제 연체 고객이 50명

→ 정밀도 50%
```

정밀도가 낮으면 정상 고객을 위험 고객으로 잘못 판단하는 경우가 많습니다.

## ④ F1 점수

> 정밀도와 재현율을 함께 고려한 점수

예를 들어 모든 사람을 위험하다고 판단하면 연체 고객은 전부 찾아낼 수 있습니다. 하지만 정상 고객도 전부 위험하다고 판단하므로 정밀도가 낮아집니다.

F1은 이 둘 사이의 균형을 볼 때 사용합니다.

## ⑤ ROC-AUC

분류 모델은 먼저 위험 점수를 출력하고, 임계값에 따라 위험/정상을 나눈다고 했습니다.

ROC-AUC는 **임계값을 여러 값으로 바꿔 보면서 모델이 두 집단을 얼마나 잘 구분하는지** 살펴보는 지표입니다.

쉽게 말하면:

> 무작위로 고른 연체 고객과 정상 고객 중, 연체 고객에게 더 높은 위험 점수를 주는가?

- AUC가 **0.5**에 가까우면 무작위로 순위를 매긴 것과 비슷합니다.
- AUC가 **1**에 가까울수록 두 집단의 순위를 잘 구분합니다.

AUC 0.95는 **정확도가 95%라는 뜻이 아닙니다.**

## 설명할 때는 이렇게

> 연체 고객이 적기 때문에 정확도만으로는 모델을 평가하기 어렵습니다. 그래서 연체 고객을 얼마나 찾아내는지 보는 재현율, 위험 판단이 얼마나 정확한지 보는 정밀도, 두 지표를 함께 보는 F1, 그리고 전체적인 구분 능력을 보는 AUC를 함께 확인했습니다.

---

# 11단계. 선수 개념: 데이터 불균형

앞에서 정확도만 보면 안 된다고 했는데, 그 원인이 바로 **데이터 불균형**입니다.

```text
정상 고객: 약 88%
연체 고객: 약 12%
```

한쪽이 훨씬 많으면 모델이 다수인 정상 고객 쪽에 치우칠 수 있습니다.

이 프로젝트는 다음 두 방법을 비교했습니다.

## ① 클래스 가중치

**연체 고객을 틀렸을 때 더 큰 벌점**을 주는 방법입니다.

시험에서 중요한 문제에 배점을 더 주는 것과 비슷합니다.

```text
정상 고객을 틀림 → 일반적인 벌점
연체 고객을 틀림 → 더 큰 벌점
```

코드에서는 `class_weight='balanced'`를 사용했습니다.

## ② SMOTE

기존 연체 고객들의 특성을 참고해 **비슷한 가상의 연체 고객 샘플**을 더 만드는 방법입니다.

예를 들면:

```text
연체 고객 A와 B의 특성을 참고
           ↓
그 사이에 있는 가상 샘플 생성
           ↓
소수 클래스 학습 자료 보강
```

이때 새 샘플은 반드시 **학습 데이터 안에서만** 만들어야 합니다. 테스트 데이터를 참고하면 데이터 누수가 발생할 수 있습니다.

## 실제 결과

| 처리 방식 | 정밀도 | 재현율 |
|---|---:|---:|
| 처리 없음 | 0.710 | 0.571 |
| 클래스 가중치 적용 | 0.496 | 0.879 |
| SMOTE 적용 | 0.514 | 0.867 |

클래스 가중치를 적용하면 연체 고객을 더 많이 찾아냈습니다. 대신 정상 고객을 위험 고객으로 잘못 판단하는 경우도 늘었습니다.

## 설명할 때는 이렇게

> 연체 고객이 소수라서 모델이 정상 고객 쪽에 치우칠 수 있었습니다. 클래스 가중치와 SMOTE를 비교한 결과, 연체 고객을 찾아내는 재현율은 높아졌지만 정밀도는 낮아졌습니다. 따라서 어떤 오류의 비용이 더 큰지에 따라 선택해야 합니다.

---

# 12단계. 회귀 모델과 규제 설명하기

이제 신용 점수를 예측하는 회귀 모델을 설명합니다.

이 프로젝트는 **Ridge**와 **Lasso**라는 두 모델을 사용했습니다.

이 둘을 설명하기 전에 **과대적합**과 **규제**를 알아야 합니다.

## 과대적합이란?

학생이 원리를 이해하지 않고 문제집의 답만 외웠다고 생각해 보세요.

```text
공부한 문제: 매우 잘 맞힘
새로운 문제: 잘 못 맞힘
```

모델도 학습 데이터의 우연한 특징까지 외우면, 새로운 고객에게는 좋은 예측을 하지 못할 수 있습니다. 이를 **과대적합**이라고 합니다.

## 규제란?

모델이 학습 데이터에 지나치게 맞춰지지 않도록 **복잡한 답에 벌점**을 주는 방법입니다.

이때 모델이 각 변수에 부여한 영향력을 **계수**라고 합니다.

예를 들어:

```text
소득의 계수: 양수 → 소득이 높을수록 점수 증가 방향
연체 횟수의 계수: 음수 → 연체가 많을수록 점수 감소 방향
```

규제는 이 계수가 지나치게 커지지 않도록 제한합니다.

## Ridge와 Lasso의 차이

### Ridge

계수를 전반적으로 작게 만듭니다.

```text
규제 전: 10, 5, 2
규제 후:  7, 3, 1
```

### Lasso

계수를 작게 만들면서 일부는 **정확히 0**으로 만들 수 있습니다.

```text
규제 전: 10, 5, 2
규제 후:  7, 3, 0
```

계수가 0이 된 변수는 해당 모델의 예측에서 사용되지 않습니다.

## Alpha란?

Alpha는 규제의 세기를 정하는 값입니다.

```text
Alpha가 작다 → 규제가 약하다
Alpha가 크다 → 규제가 강하다
```

이번 프로젝트에서는 여러 Alpha를 비교했습니다.

너무 강하게 규제한 Lasso에서는 모든 계수가 0이 되어 예측 성능이 크게 떨어졌습니다.

## 설명할 때는 이렇게

> 신용 점수 예측에는 Ridge와 Lasso를 사용했습니다. 두 모델 모두 계수가 지나치게 커지는 것을 규제로 제한합니다. Lasso는 일부 계수를 0으로 만들 수도 있습니다. 규제가 너무 강하면 필요한 정보까지 제거되어 성능이 떨어질 수 있다는 점을 확인했습니다.

---

# 13단계. 회귀 모델의 성적표 읽기

신용 점수 예측은 숫자를 맞히는 문제이므로, 분류의 정확도나 재현율 대신 **예측 점수와 실제 점수의 차이**를 봅니다.

## MAE

> 예측값과 실제값의 차이를 평균적으로 얼마나 냈는가?

```text
실제 점수: 400점
예측 점수: 420점

→ 오차: 20점
```

이런 오차의 절댓값을 평균한 것이 MAE입니다.

## RMSE

RMSE도 오차를 측정하지만, **큰 오차를 더 무겁게 취급**합니다.

예를 들어 대부분 10점 이내로 틀렸지만 한 고객에게 100점 차이로 틀렸다면, 그 큰 오차의 영향이 MAE보다 크게 반영됩니다.

## R²

> 단순히 모든 고객에게 평균 점수를 예측하는 기준과 비교해 얼마나 나아졌는가?

일반적으로 1에 가까울수록 좋습니다. 0보다 작을 수도 있는데, 이 경우 평균만 예측하는 기준보다 나쁘다는 뜻입니다.

## 실제 결과

| 모델 | MAE | RMSE | R² |
|---|---:|---:|---:|
| Ridge | 23.9 | 30.1 | 0.861 |
| Lasso | 23.9 | 30.1 | 0.861 |

예를 들어 Ridge의 MAE 23.9는 **예측 점수가 실제 점수와 평균적으로 약 24점 차이** 났다는 뜻입니다.

## 설명할 때는 이렇게

> 회귀 모델의 성능은 MAE, RMSE, R²로 평가했습니다. Ridge와 Lasso 모두 평균적으로 약 24점의 오차를 보였습니다. 데이터 생성 과정에 무작위 잡음이 들어가 있기 때문에 모든 고객의 점수를 완벽하게 맞히기는 어렵습니다.

# 14단계. 분류 모델: 로지스틱 회귀와 랜덤 포레스트

## ① 로지스틱 회귀

이름에 ‘회귀’가 들어가지만, 여기서는 **연체 여부를 분류하는 모델**입니다.

고객 정보에 각각 가중치를 부여해 위험 점수를 계산한 뒤, 이를 0과 1 사이의 값으로 변환합니다.

```text
소득, 부채 비율, 연체 횟수
           ↓
      가중치를 적용
           ↓
       연체 위험 점수
```

구조가 비교적 단순하고 예측이 빠르다는 장점이 있습니다.

## ② 결정 트리

결정 트리는 여러 질문을 이어가며 판단합니다.

```text
연체 횟수가 많은가?
       │
   ┌───┴───┐
  예       아니요
   │          │
소득이 낮은가?  부채가 높은가?
```

트리 하나는 학습 데이터가 조금만 달라져도 판단 기준이 달라질 수 있습니다.

## ③ 랜덤 포레스트

랜덤 포레스트는 이름처럼 **여러 결정 트리를 모은 모델**입니다.

```text
트리 1의 판단 ─┐
트리 2의 판단 ─┤
트리 3의 판단 ─┼─→ 결과를 종합해 예측
      ...     ─┤
트리 N의 판단 ─┘
```

여러 트리의 결과를 종합해 트리 하나의 판단이 흔들리는 영향을 줄입니다.

이처럼 여러 모델의 결과를 모으는 방식을 **앙상블**이라고 합니다.

## 설명할 때는 이렇게

> 연체 여부를 예측하기 위해 로지스틱 회귀와 랜덤 포레스트를 사용했습니다. 랜덤 포레스트는 여러 결정 트리의 결과를 종합하는 앙상블 모델입니다. 실험에서는 트리 하나보다 예측 결과의 흔들림이 작았습니다.

# 15단계. 교차 검증과 GridSearchCV

## 교차 검증이란?

모델 설정을 고를 때 학습 데이터를 한 번만 나누면, 우연히 그 분할에서만 좋은 점수가 나올 수 있습니다.

그래서 학습 데이터를 다섯 부분으로 나누고, 검증에 사용하는 부분을 바꿔 가며 다섯 번 평가합니다.

```text
1회: 검증 / 학습 / 학습 / 학습 / 학습
2회: 학습 / 검증 / 학습 / 학습 / 학습
3회: 학습 / 학습 / 검증 / 학습 / 학습
4회: 학습 / 학습 / 학습 / 검증 / 학습
5회: 학습 / 학습 / 학습 / 학습 / 검증
```

이를 **5겹 교차 검증**이라고 합니다.

## GridSearchCV란?

랜덤 포레스트에는 사람이 정해야 하는 설정이 있습니다.

예를 들면:

- 트리를 몇 개 만들 것인가?
- 트리를 얼마나 깊게 만들 것인가?
- 한 그룹에 최소 몇 명의 고객을 남길 것인가?

**GridSearchCV**는 이런 설정의 여러 조합을 교차 검증으로 비교해 좋은 조합을 찾는 방법입니다.

프로젝트에서는 **60개 조합**을 비교했고, 교차 검증의 F1 점수를 기준으로 선택했습니다.

다만 튜닝했다고 테스트 성능이 반드시 높아지는 것은 아닙니다. 이 실험에서는 튜닝 전후 테스트 F1이 크게 다르지 않았고, 튜닝한 모델이 약간 낮았습니다.

## 설명할 때는 이렇게

> 랜덤 포레스트의 설정을 임의로 하나 정하지 않고, 60개 조합을 5겹 교차 검증으로 비교했습니다. 다만 최적 설정을 찾더라도 새로운 테스트 데이터에서 항상 더 좋은 성능을 보장하지는 않습니다.

---

# 16단계. 최종 결과 설명하기

이제 모든 선수 개념을 설명했으므로 결과표를 보여주면 됩니다.

| 모델 | 정확도 | 재현율 | F1 | AUC |
|---|---:|---:|---:|---:|
| 규칙 기반 | 0.850 | 0.717 | 0.534 | 0.878 |
| 로지스틱 회귀 | 0.878 | 0.879 | 0.635 | 0.950 |
| 랜덤 포레스트, 튜닝 | 0.897 | 0.771 | 0.642 | 0.942 |

## 결과 1. 머신러닝이 규칙 기반보다 좋은 결과를 냈다

튜닝한 랜덤 포레스트의 F1은 **0.642**, 규칙 기반 모델은 **0.534**였습니다.

```text
F1: 0.534 → 0.642
AUC: 0.878 → 0.942
```

따라서 이 가상 데이터에서는 머신러닝이 사람이 만든 규칙보다 연체 위험을 더 잘 구분했습니다.

## 결과 2. 복잡한 모델이 항상 가장 좋은 것은 아니다

로지스틱 회귀의 AUC는 **0.950**, 랜덤 포레스트는 **0.942**였습니다.

이 데이터의 신용 점수는 소득, 부채 비율, 연체 횟수를 더하고 빼는 비교적 단순한 수식으로 만들어졌습니다. 그래서 선형 관계를 표현하는 로지스틱 회귀도 좋은 성능을 낸 것으로 해석할 수 있습니다.

## 결과 3. 하나의 지표만으로 모델을 고르기 어렵다

로지스틱 회귀는 재현율이 더 높았고, 튜닝된 랜덤 포레스트는 F1이 근소하게 높았습니다.

어떤 모델을 선택할지는 다음 질문에 따라 달라집니다.

```text
연체 고객을 놓치는 비용이 더 큰가?
정상 고객을 위험 고객으로 판단하는 비용이 더 큰가?
예측 속도나 모델 크기가 중요한가?
```

## 설명할 때는 이렇게

> 이번 데이터에서는 머신러닝이 규칙 기반 모델보다 F1과 AUC에서 좋은 결과를 냈습니다. 다만 랜덤 포레스트가 모든 지표에서 로지스틱 회귀보다 좋았던 것은 아닙니다. 모델 선택은 성능뿐 아니라 어떤 실수를 더 중요하게 보는지와 운영 비용을 함께 고려해야 합니다.

# 17단계. 마지막으로 한계 설명하기

평가에서는 좋은 결과뿐 아니라 **그 결과로 무엇을 말할 수 없는지**도 설명하면 좋습니다.

## 이렇게 마무리할 수 있습니다

> 이 프로젝트의 데이터는 실제 은행 고객 정보가 아니라 정해진 수식으로 생성한 가상 데이터입니다. 그래서 이 결과는 머신러닝 파이프라인과 모델 평가 방법을 연습한 결과로 이해해야 합니다.
>
> 실제 대출 심사에 사용하려면 실제 데이터에서 성능을 검증하고, 예측 시점에 사용할 수 있는 정보인지 확인해야 합니다. 또 승인·거절·보류 기준과 각 판단의 비용도 별도로 정해야 합니다.

# 전체 내용을 3분 정도로 설명한다면

아래는 위 내용을 짧게 연결한 발표 예시입니다.

> 이 과제는 가상의 고객 정보를 이용해 신용 점수와 연체 위험을 예측하고, 사람이 만든 규칙과 머신러닝 모델의 성능을 비교하는 프로젝트입니다.
>
> 먼저 가상의 고객 10,000명에 대해 나이, 소득, 부채 비율, 최근 연체 횟수 등의 데이터를 만들었습니다. 예측해야 하는 정답은 두 가지로, 신용 점수처럼 숫자를 예측하는 문제는 회귀, 연체 여부처럼 종류를 구분하는 문제는 분류입니다.
>
> 데이터를 학습용 8,000명과 테스트용 2,000명으로 나눴습니다. 전처리는 결측값 처리, 스케일링, 범주형 인코딩을 파이프라인으로 묶었고, 테스트 정보가 학습에 섞이지 않도록 학습 데이터로만 전처리 기준을 계산했습니다.
>
> 비교 기준으로는 사람이 만든 다섯 개 규칙을 사용했습니다. 두 개 이상의 규칙에 해당하면 연체 위험으로 판단했습니다. 머신러닝 모델로는 회귀에 Ridge와 Lasso를, 분류에 로지스틱 회귀와 랜덤 포레스트를 사용했습니다.
>
> 연체 고객은 전체의 약 12%로 적기 때문에 정확도만 보면 모델의 성능을 오해할 수 있습니다. 그래서 연체 고객을 얼마나 찾아냈는지 보는 재현율과 정밀도, F1, AUC를 함께 확인했습니다. 클래스 가중치와 SMOTE를 적용한 실험에서는 재현율이 높아지는 대신 정밀도가 낮아졌습니다.
>
> 최종적으로 머신러닝 모델은 규칙 기반 모델보다 F1과 AUC에서 좋은 결과를 냈습니다. 다만 로지스틱 회귀도 랜덤 포레스트만큼 좋은 결과를 보여, 복잡한 모델이 항상 더 좋은 것은 아니라는 점을 확인했습니다.
>
> 신용 점수 예측에서는 Ridge와 Lasso가 평균적으로 약 24점의 오차를 보였습니다. 규제를 너무 강하게 적용하면 필요한 정보까지 제거돼 성능이 떨어질 수 있다는 점도 확인했습니다.
>
> 다만 이번 데이터는 수식으로 만든 가상 데이터이므로, 실제 대출 심사에 사용하려면 실제 데이터와 업무 기준을 바탕으로 추가 검증이 필요합니다.
